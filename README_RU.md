# mihomo-remnasub-ros

Контейнер Mihomo для MikroTik RouterOS, который запускает полный YAML-профиль по подписке, например выдаваемый Remnawave.

Подписка не превращается в `proxy-provider`: это полноценная конфигурация Mihomo. Контейнер хранит полученный YAML и добавляет только локальные переопределения. Первое из них - настраиваемый входящий `mixed` listener для локальной сети. Офлайн-веб-панель работает на BusyBox `httpd` и доступна на порту `80`.

## Что сохраняется

В смонтированной директории `/etc/mihomo` создаются:

- `remnasub/profile.conf` - URL, HTTP-заголовки и локальные настройки listener;
- `remnasub/source.yaml` - последний успешно скачанный YAML;
- `remnasub/source.meta` - время и размер последнего скачивания.

Итоговый YAML создаётся в `/dev/shm/remnasub/config.yaml`, поэтому временные файлы не изнашивают накопитель роутера.

## Веб-панель

Откройте `http://IP_КОНТЕЙНЕРА/` и задайте:

- URL полной YAML-подписки;
- дополнительные HTTP-заголовки, по одному в строке;
- интервал обновления и таймаут;
- локальный `mixed` listener и пользователей в формате `логин#пароль`.

После сохранения профиль обновляется сразу. Mihomo перезапускается только если скачанный YAML вместе с локальными переопределениями прошёл `mihomo -t`. На странице «Конфигурация» доступны исходный и итоговый YAML.

Панель защищена HTTP Basic Auth. Используйте ENV `BASIC_AUTH_USER` и `BASIC_AUTH_HASH`; `BASIC_AUTH=off` допустим только в изолированной доверенной сети.

## Аргументы сборки

`MIHOMO_CUSTOM_CORE=0` использует официальный релиз MetaCubeX. Для совместимого кастомного ядра задайте `MIHOMO_CUSTOM_CORE=1` и при необходимости поменяйте `MIHOMO_CUSTOM_REPO`.

Поддерживаются amd64 (`AMD64VERSION=v1|v2|v3|v4`), arm64, armv7 и armv5.
